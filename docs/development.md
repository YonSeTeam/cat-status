# cat-status: заметки для разработки

Как устроен мод, о какие правила движка уже спотыкались и как живёт сервер. Что это и как поставить, написано в [README](../README.md).

## Что где лежит

```
.claude-plugin/plugin.json   манифест плагина
hooks/hooks.json             указывает на register.tsx
hooks/register.tsx           весь мод: спрайты, полоска, команды /cat, сеть
types/index.d.ts             контракт $.state (каждое значение мода объявлено тут)
server/server.js             сервер присутствия, чистый node без зависимостей
server/Dockerfile
server/public/install.md     инструкция, которой следует Claude Code друга
scripts/                     деплой сервера, упаковка архива, проверка типов
tests/                       тесты, которые гоняет `claude plugin test .`
docs/                        эти заметки и картинки для README
```

Корень репозитория это и есть папка плагина: он лежит в `~/.claude/mods/cat-status`, а `CLAUDE_CODE_PLUGIN_DIRS` в `~/.claude/settings.json` указывает на неё. Поэтому правки в этих файлах работают сразу, без копирования.

## Как это подключено

В `~/.claude/settings.json`, блок `env`:

```json
"CLAUDE_CODE_PLUGIN_DIRS": "C:\\Users\\<имя>\\.claude\\mods\\cat-status",
"CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1",
"CLAUDE_CODE_PLUGIN_DIR_WATCH": "1"
```

Без `PLUGIN_DIR_WATCH` приложение читает мод один раз при старте сессии и не перезагружает его, причём молча. Если правка «не работает», сначала проверь, что запущена новая версия (например, по тексту `/cat`).

## Правка мода

1. Меняй `hooks/register.tsx` (и `types/index.d.ts`, если появилось новое значение в `$.state`).
2. `scripts/typecheck.sh` проверяет типы против API установленного Claude Code. Если на машине есть Node, `tsc` запускается локально, иначе в одноразовом контейнере на сервере из `CAT_SERVER`.
3. `claude plugin test .` из корня репозитория гоняет тесты из `tests/` прямо в движке Claude Code, Node для них не нужен. В архив для друзей тесты не попадают.
4. Мод перезагрузится сам. Если не загрузился, в расшифровке сессии появится строка `cat-status: reload failed, the previous version stays loaded: ...`, а работать продолжит прежняя версия.
5. Когда версию нужно отдать друзьям: `scripts/publish-zip.sh`. Иначе они ставят старый архив.

Правила движка, о которые уже спотыкались:

- `$` можно передавать только в функции, объявленные на верхнем уровне файла (не внутри `register`). `tsc` этого не видит, видно только по `reload failed`.
- Работа с `$.state` идёт через `atom`, `read` и `update`. Значение, которого нет в `types/index.d.ts`, не загрузится.
- `turn.complete` приходит и для субагентов (у события есть `agentId`). Считать их ходы задачами нельзя. Задачей считается только ход с `reason === 'answer'`: прерванный Esc или упавший ход не в счёт.
- Котята это агенты сессии. Котёнок приходит на `agent.spawn` или на `classic.SubagentStart`, а уходит на `turn.complete` агента.
  - `SubagentStart` движок шлёт в начале каждого прогона агента: для агентов из инструмента Agent, для агентов воркфлоу и для агента, которого разбудили сообщением.
  - Раз в 2 секунды мод сверяется с `$.agent.list()`. Так находятся агенты, о которых не было события, и уходят те, кого список больше не показывает в работе. Агентов воркфлоу в этом списке нет.
- Служебные циклы движка (запись памяти после хода, «сон», сжатие) тоже шлют `tool.call` с `agentId` того же вида, что у агента. Но `SubagentStart` у них нет, поэтому котят у них нет. Котёнка по одному виду id не заводить: так появятся призраки на 30 минут.
- Статус `waiting` в `$.agent.list()` значит, что агент ждёт свою фоновую работу или дочернего агента, а не человека. Поэтому `?` над котёнком ставит только диалог разрешения или вопрос агента. Агент, который закончил свой ход, но держит фоновую команду, остаётся в списке как `waiting`. Котёнок его уже ушёл и не возвращается.
- Инструменты агентов не трогают кошку: её строку, счётчик действий, грусть от ошибок и ожидание. Иначе фоновые агенты дописывали действия в уже закрытую задачу, а конец любого их действия гасил «жду тебя!» у кошки. Пока агент ждёт человека, кошка зовёт вместе с его котёнком, даже если сама отдыхает.
- Статистику за всё время (`lifetime` в `$.store`) пишут и ход, и агенты, иногда в одну и ту же секунду. Поэтому все изменения идут через одну очередь (`changeLifetime`).
- Контекст считается от окна автокомпакта, как в самом приложении: при `autoCompactWindow: 500000` на модели с окном 1M полоска полная на 500k. `context` из `$.session.usage()` и `session.measure` меряет только окно модели. Окно автокомпакта есть лишь в разборе (`$.session.usage({ breakdown: 'summary' })`, `rawMaxTokens`). Разбор `summary` считается локально и запросов не шлёт, но он не бесплатный, поэтому кот читает его раз в начале сессии и раз на ход. Если автокомпакт выключен, считается от окна модели.
- На десктопе `Svg` меряется в CSS-пикселях, а `Box` в клетках. Поэтому картинки лежат в `Box` фиксированной ширины: двор по 4 своих пикселя на клетку (`DESKTOP_YARD_PX`), полоски лимитов в `DESKTOP_BAR_W`. Иначе расчёт ширины полоски врёт.
- Все коты живут в одном дворе слева (`yard`): у каждого своя полоса, где он гуляет, спит и прыгает, а бегают и догоняют друг друга они по всему двору. Двор растёт с числом друзей; когда места мало, сначала пропадают полоски у лимитов (цифры остаются), потом пояснения к ним. Кадр берётся из часов, а не из атома `frame`, поэтому кот друга шагает одинаково на всех экранах.
- Котята живут в полосе своей кошки и своего места не занимают. Ни полосы, ни двор, ни подпись, ни счётчики не зависят от числа котят: котята приходят и уходят вместе с агентами, а от этого не должен сдвигаться ни один кот. В узком окне котята толпятся у мамы, а в узком дворе не бегут за ней цепочкой: им некуда отстать.
- Пока котята работают, а кошка свободна, она по очереди сидит и лежит, но не засыпает. Котята по очереди приходят к ней: к лежащей забираются на спину, к сидящей подходят потереться. В каждом круге есть ход, когда никто не приходит, так что и одинокий котёнок успевает поиграть. Когда кошка бегает, котята бегут за ней цепочкой.
- Приложение не проигрывает анимацию внутри SVG: кадр рисуется целиком, а меняет его атом `frame`, тикающий каждые 250 мс.
- Все слова мода живут в словарях `RU` и `EN` в начале `register.tsx`; `EN` обязан повторять `RU` ключ в ключ, это проверяет тип `Words`. Новый текст добавляй в оба. Модульное `tr` каждый хук берёт из атома `lang` первым делом (`useLang`): перезагрузка мода сбрасывает модульные значения, а `$.state` хранит.
- Язык выбирается при старте сессии: сохранённый `/cat lang`, иначе русский для кота со статистикой из прежних версий, иначе язык системы (`Intl`), и этот первый выбор сохраняется. Фразы с аргументами для `/cat share` начинаются с `tr.run` или `tr.search`: `forFriends` отрезает по ним всё, что дальше.

## Сервер

В моде нет адреса сервера: каждый поднимает свой и задаёт его командой `/cat server <адрес>` (хранится в `$.store` рядом с комнатой). Без адреса мод не делает ни одного сетевого запроса. Сервер живёт в Docker, контейнер `cat-sync`. Состояние комнат хранится в памяти, при перезапуске комнаты пустеют и заполняются заново за один пульс (8 с).

`scripts/deploy-server.sh` загружает `server/`, пересобирает образ и перезапускает контейнер. Хост, ключ, каталог и внешний адрес задаются переменными `CAT_SERVER` (обязательна), `CAT_SSH_KEY`, `CAT_REMOTE_DIR`, `CAT_PUBLIC_URL` (см. `scripts/env.sh`).

`/install` отдаёт `server/public/install.md`, подставив вместо `{{SERVER}}` адрес сервера: `PUBLIC_URL` из окружения контейнера, если он задан (сервер за прокси с TLS), иначе хост, на который пришёл запрос.

Эндпоинты:

| Запрос | Что делает |
| --- | --- |
| `GET /health` | жив ли сервер, сколько комнат |
| `POST /beat` | пульс: имя, цвет, статус, настроение, задачи за день, 5-часовой лимит (и когда он сбросится), число котят. Лимит хранится по сессиям: сессия без показаний не затирает лимит другой, берётся самое свежее окно. Отвечает составом комнаты и накопившимися событиями |
| `POST /poke` | `pet`, `meow`, `react`, `say`: событие ждёт на сервере, пока адресат не сделает следующий пульс |
| `POST /leave` | выйти из комнаты сразу |
| `GET /room` | состав комнаты |
| `GET /install`, `GET /cat-status.zip` | инструкция и архив для друга, из `server/public` |

Комната это общий секрет: знаешь код, значит заходишь. Что именно делает Claude («правит main.py»), на сервер уходит только при `/cat share on`, и то без аргументов команд и без текста поиска: «запускает npm», «ищет».

## Команды `/cat`

`/cat` без аргументов показывает статистику и полную справку. Кратко:

- вид: `compact`, `full`, `hide`, `show`, `cache 5|60`, `lang ru|en`, `stats`
- комната: `server <адрес>`, `friend new`, `friend <код>`, `friend`, `name`, `color`, `share`, `notify`, `who`, `invite`, `preview`, `solo`
- с друзьями: `meow`, `say`, `mood`; кнопки «погладить», «мяу», 👍 🔥 😹 под котом друга

## Позвать друга

`/cat invite` выдаёт готовое сообщение: его Claude Code читает `/install`, качает архив и сам прописывает настройки, а друг потом пишет `/cat server <адрес>` и `/cat friend <код>`. Вручную: распаковать `cat-status.zip` в `~/.claude/mods/`, добавить три ключа выше и перезапустить Claude Code.
